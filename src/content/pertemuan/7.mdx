## D. Tiga Jenjang Pemodelan Data

Perancangan basis data berjalan melalui tiga jenjang model dengan tingkat abstraksi yang berbeda:

- **CDM (Conceptual Data Model)**: sepenuhnya bebas DBMS: *apa* datanya (ERD, Pertemuan 2–3)
- **LDM (Logical Data Model)**: bebas DBMS, tetapi sudah berupa tabel + normalisasi (Pertemuan 4–6)
- **PDM (Physical Data Model)**: menyesuaikan dengan **spesifikasi DBMS nyata** (tipe data, constraint, DDL)

## E. Menentukan Tipe Data

Setiap atribut pada LDM harus dipetakan ke **tipe data** yang tersedia di DBMS target. Pemilihan tipe data yang tepat menjaga efisiensi penyimpanan dan integritas nilai.

### Peta Tipe Data Antar DBMS

| Kebutuhan Data | MySQL | PostgreSQL | SQLite |
|---|---|---|---|
| Bilangan bulat kecil | `SMALLINT` | `SMALLINT` | `INTEGER` |
| Bilangan bulat | `INT` | `INTEGER` | `INTEGER` |
| Bilangan besar | `BIGINT` | `BIGINT` | `INTEGER` |
| Teks pendek | `VARCHAR(n)` | `VARCHAR(n)` | `TEXT` |
| Teks panjang | `TEXT` | `TEXT` | `TEXT` |
| Angka desimal | `DECIMAL(p,s)` | `NUMERIC(p,s)` | `NUMERIC` |
| Tanggal | `DATE` | `DATE` | `TEXT` (ISO) |
| Waktu + tanggal | `DATETIME` / `TIMESTAMP` | `TIMESTAMP` | `TEXT` (ISO) |
| Logika benar/salah | `BOOLEAN` (alias `TINYINT(1)`) | `BOOLEAN` | `INTEGER` 0/1 |
| Kunci otomatis | `INT AUTO_INCREMENT` | `SERIAL` / `BIGSERIAL` | `INTEGER PRIMARY KEY AUTOINCREMENT` |

<div class="callout">
  <span class="callout__label">Tips Memilih</span>
  <p><strong>Atribut kode</strong> (nim, kode_mk) → teks pendek <code>VARCHAR(n)</code>. <strong>Umur/jumlah</strong> → bilangan bulat. <strong>Harga/SKS/bobot</strong> → desimal dengan presisi. <strong>Tanggal</strong> → tipe tanggal (bukan teks bebas agar bisa diurutkan/dirrentang). Pilih ukuran kolom <em>secukupnya</em>, terlalu besar membuang ruang, terlalu kecil membuat data terpotong.</p>
</div>

## F. Menetapkan Key dan Constraint

**Constraint** adalah aturan yang dipaksakan DBMS untuk menjaga integritas data:

<table class="dtable">
  <thead><tr><th>Constraint</th><th>Contoh DDL</th><th>Fungsi</th></tr></thead>
  <tbody>
    <tr><td><code>PRIMARY KEY</code></td><td><code>nim VARCHAR(10) PRIMARY KEY</code></td><td>Identitas unik & wajib</td></tr>
    <tr><td><code>NOT NULL</code></td><td><code>nama VARCHAR(50) NOT NULL</code></td><td>Kolom tidak boleh kosong</td></tr>
    <tr><td><code>UNIQUE</code></td><td><code>email VARCHAR(80) UNIQUE</code></td><td>Nilai unik, boleh kosong</td></tr>
    <tr><td><code>DEFAULT</code></td><td><code>sks SMALLINT DEFAULT 3</code></td><td>Nilai bawaan bila tidak diisi</td></tr>
    <tr><td><code>CHECK</code></td><td><code>sks SMALLINT CHECK (sks BETWEEN 1 AND 6)</code></td><td>Validasi nilai pada range</td></tr>
    <tr><td><code>FOREIGN KEY</code></td><td><code>CONSTRAINT fk ... FOREIGN KEY (kode_prodi) REFERENCES program_studi(kode_prodi)</code></td><td>Integritas referensial antar tabel</td></tr>
  </tbody>
</table>

## G. Studi Kasus: PDM SIAKAD

Transformasikan skema relasional SIAKAD (Pertemuan 4) menjadi **PDM** dengan tipe data MySQL:

### G.1 Pengecekan Atribut → Tipe Data

| Atribut | Kebutuhan Nilai | Tipe Data MySQL |
|---|---|---|
| `kode_prodi`, `kode_mk` | kode singkat | `VARCHAR(10)` |
| `nim`, `nip` | kode panjang maks. 12 | `VARCHAR(12)` |
| `nama`, `nama_prodi` | teks pendek | `VARCHAR(50–60)` |
| `alamat`, `bidang_keahlian` | teks lebih panjang | `VARCHAR(120)` |
| `email` | teks unik | `VARCHAR(80) UNIQUE` |
| `tgl_lahir` | tanggal | `DATE` |
| `sks` | 1–6 | `SMALLINT CHECK (sks BETWEEN 1 AND 6)` |
| `nilai`, `grade` | 1–2 karakter | `CHAR(2)` |

### G.2 DDL PDM (MySQL)

```sql
CREATE TABLE program_studi (
  kode_prodi VARCHAR(10) PRIMARY KEY,
  nama_prodi VARCHAR(60) NOT NULL,
  fakultas   VARCHAR(60)
);

CREATE TABLE mahasiswa (
  nim        VARCHAR(12) PRIMARY KEY,
  nama       VARCHAR(50) NOT NULL,
  alamat     VARCHAR(120),
  email      VARCHAR(80) UNIQUE,
  tgl_lahir  DATE,
  kode_prodi VARCHAR(10) NOT NULL,
  CONSTRAINT fk_mhs_prodi FOREIGN KEY (kode_prodi)
    REFERENCES program_studi(kode_prodi)
);

CREATE TABLE dosen (
  nip             VARCHAR(12) PRIMARY KEY,
  nama_dosen      VARCHAR(50) NOT NULL,
  bidang_keahlian VARCHAR(60)
);

CREATE TABLE matakuliah (
  kode_mk   VARCHAR(10) PRIMARY KEY,
  nama_mk   VARCHAR(60) NOT NULL,
  sks       SMALLINT DEFAULT 3 CHECK (sks BETWEEN 1 AND 6),
  semester  VARCHAR(6),
  nip_dosen VARCHAR(12),
  CONSTRAINT fk_mk_dosen FOREIGN KEY (nip_dosen)
    REFERENCES dosen(nip)
);

CREATE TABLE nilai (
  nim     VARCHAR(12) NOT NULL,
  kode_mk VARCHAR(10) NOT NULL,
  nilai   CHAR(2),
  grade   CHAR(2),
  PRIMARY KEY (nim, kode_mk),
  CONSTRAINT fk_n_mhs FOREIGN KEY (nim) REFERENCES mahasiswa(nim),
  CONSTRAINT fk_n_mk  FOREIGN KEY (kode_mk) REFERENCES matakuliah(kode_mk)
);
```

<div class="callout">
  <span class="callout__label">Perhatikan</span>
  <p>Jumlah & nama tabel <strong>persis sama</strong> dengan hasil LDM/normalisasi (Pertemuan 4–6). Yang berubah hanya detail <em>fisik</em>: tipe data, ukuran kolom, dan constraint. Itulah esensi PDM.</p>
</div>

## H. Praktik PDM dengan dbdiagram.io / draw.io

PDM juga bisa dirancang dan divisualisasikan dengan tool, sesuai rekomendasi RPS.

### Sintaks dbdiagram.io (contoh subset SIAKAD)

```text
Table program_studi {
  kode_prodi varchar(10) [pk]
  nama_prodi varchar(60) [not null]
  fakultas varchar(60)
}

Table mahasiswa {
  nim varchar(12) [pk]
  nama varchar(50) [not null]
  email varchar(80) [unique]
  tgl_lahir date
  kode_prodi varchar(10) [ref: > program_studi.kode_prodi]
}

Table matakuliah {
  kode_mk varchar(10) [pk]
  nama_mk varchar(60) [not null]
  sks smallint [default: 3]
  nip_dosen varchar(12) [ref: > dosen.nip]
}

Table nilai {
  nim varchar(12)
  kode_mk varchar(10)
  nilai char(2)
  grade char(2)
  indexes { (nim, kode_mk) [pk] }
  refs {
    > mahasiswa.nim
    > matakuliah.kode_mk
  }
}
```

<ol class="steps">
  <li>Buka <strong>dbdiagram.io</strong> (browser, bisa dari smartphone) atau <strong>draw.io</strong>.</li>
  <li>Tulis skema PDM seperti sintak di atas, atau gambar kotak tabel secara visual.</li>
  <li>Hubungkan antartabel dengan garis relasi (kardinalitas).</li>
  <li>Ekspor DDL (dbdiagram.io menyediakan tombol <em>Export → SQL</em>) untuk dipakai pada Pertemuan 11–13.</li>
</ol>

## K. Rangkuman

- Perancangan berjenjang: **CDM → LDM → PDM**, dari abstrak menuju spesifik DBMS
- **PDM** menentukan tipe data, ukuran kolom, key, dan constraint
- Pemilihan tipe data menyesuaikan DBMS target (MySQL vs PostgreSQL vs SQLite)
- Constraint (PRIMARY KEY, NOT NULL, UNIQUE, DEFAULT, CHECK, FOREIGN KEY) menjaga integritas
- Struktur tabel PDM **sama** dengan LDM hasil normalisasi: hanya detail fisiknya yang ditambahkan
- PDM siap dieksekusi menjadi DDL pada praktikum DBMS (Pertemuan 9–15) dan dinilai pada UTS (proyek tahap 1)
